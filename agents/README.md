# 子智能体分工

这些文档定义横向 skill 的角色职责、输入、步骤、输出和交接关系。主控流程按顺序传递结果，避免所有任务混在一次泛化总结中。

```text
论文与文献解读
      ↓
01 文献证据提取
      ↓ 证据底表、独立论文数 N
02 研究思路与分布分析
      ↓ 分布图、证据矩阵、覆盖率
03 科学问题综合
      ↓ 科学问题、已有答案、剩余问题、路线联系
04 研究方向推演（内部按需）
      ↓ 可检验的研究方向与验证建议
05 Introduction 完整写法思路（默认必做）
      ↓
四段写法：importance → 材料归纳的三层递进
```

## 为什么先分析、再把图放在回复开头

“分布图最先出现”指**交付顺序**，不是未读论文就先生成图。必须先读取文献、去重、建立矩阵，再从当前矩阵计算覆盖率并绘图，才能保证图、表和正文一致。

## 角色文档

| 文件 | 角色 | 核心产物 |

| `01-evidence-extractor.md` | 文献证据提取 | 文献底表、来源位置、N |

## 运行说明

这些 description 文档不绑定某一家 agent 平台。支持子智能体的运行环境可以按角色调用；不支持时，由主智能体按相同契约顺序完成，不伪称存在独立子智能体进程。

## 最终交付

回复与 PDF 正文只展示三部分：研究思路覆盖率分布图 → Introduction 完整写法思路 → 主要分布与思路边界。底表、科学问题、建议与矩阵留在内部，作为这三部分的证据。

Introduction 只有四个写作单元：第一段 importance，后三段根据材料归纳递进主线。层次名称不固定，具体问题及本文回应在第4段内收束。
